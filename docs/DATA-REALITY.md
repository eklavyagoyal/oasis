# OASIS data reality

## What was inspected

- The shipped `dashboard/public/data.js` is byte-identical to `dashboard/demo.zip:data.js`. The archive’s 606 referenced media paths all exist.
- That bundle contains 25,092 RF detection rows and 1,300 position fixes; it declares 10 sensors. It has 600 EO images, 2 satellite images, 4 IQ spectrogram images, and no audio. `MW.provenance.skipped_sensor_types` includes `microphone`.
- Its audit is 9 PASS, 0 FAIL, 1 SKIP, with `baseline: null`. That is an audit of generated run data, not field validation or an LLM comparison.
- The bundle has real Copernicus DEM provenance and a Sentinel-2 scene identifier/credit (`MW.terrain.texture.scene = S2B_36UUV_20241107_0_L2A`). Most sensor readings/media are generated by OASIS; “recorded” does not mean real-world instrument data.

## UI reading → source → reality

| UI value | Meaning / unit / angle convention | Exact source and transformation | Reality |
|---|---|---|---|
| Signal-ledger rate | RF rows counted in the previous second; `DET/s` is a count, not a physical detection probability. | `dashboard/src/main.js::updateUI` reads `MW.rf[*].t`; `dashboard/scripts/export_data.py::main` writes RF detections. | Synthetic RF detections in the Python run. Browser game intervals are not RF rows. |
| Bearing number and ray | `MW.rf[id].brg`; degrees clockwise from true north (0° N, 90° E). | `mirrorworld/sensors/rf_df.py::_receive` creates `bearing_deg = true_az + site bias + modeled error`; exporter maps `detections.csv.bearing_deg` to `rf.*.brg`; `dashboard/src/layers/rf.js::rayPositions` draws it. | A simulated, noisy direction estimate; not measured radio direction. |
| Bearing uncertainty | `MW.rf[id].std`; nominal 1σ angular spread in degrees. | `_sigma_deg` → `detections.csv.bearing_std_deg` → exporter `rf.*.std`. It uses SNR and a receiver floor; the emitted estimate does not include the realized extra NLOS/wild error. | Model-reported estimate, not calibrated field uncertainty. |
| SNR | `MW.rf[id].snr`, dB; used to fade ray brightness, not shown as a numeric readout. | `_receive` combines modeled received power, thermal/interference noise, then adds random reporting error to `snr_db`; exporter maps to `rf.*.snr`; `layers/rf.js` uses it for opacity. | Synthetic receiver-model output, not a measured SNR. |
| Received power chart | `MW.rf[id].pwr`, dBm. | `_receive`: configured EIRP + antenna gain − modeled path loss/shadowing + fading and reporting noise; exporter maps `detections.csv.power_dbm` to `rf.*.pwr`; `panels/inspector.js` plots it. | Simulated received power; no physical receiver produced it. |
| Position fix | `MW.fixes.lat/lon`; estimated location from crossed RF bearings. | `mirrorworld/sensors/rf_df.py::_fuse` performs weighted least-squares line crossing; exporter maps `fused/fixes.csv`. | Synthetic estimate from synthetic bearings. |
| Fix uncertainty | `cep50` and `smaj`/`smin` in metres; `orient` in degrees modulo 180, clockwise from true north. The map ellipse uses `smaj`, `smin`, `orient`. | `_fuse` derives axes/orientation from the crossing covariance; exporter maps `semi_major_m`, `semi_minor_m`, `orient_deg`, `cep50_m` to `MW.fixes`. | Statistical model estimate, not a confidence region validated against field observations. |
| Fix error | Metres from the fix to its associated truth object; UI labels latest/median scored fixes. | `_fuse` computes `error_m` from the simulated truth state; `export_data.py::main` joins `answer_key/fused.csv` and exports `MW.fixes.err`; inspector reads that answer-key field. | Post-hoc synthetic score, not sensor-reported accuracy. |
| Truth altitude / AGL / speed | `objects[].alt` is MSL metres; inspector derives AGL by subtracting DEM height and ground speed from adjacent position samples. | `mirrorworld/truth.py::simulate` creates truth from waypoints/speed and DEM height; exporter downsamples truth to `MW.objects`; `dashboard/src/data.js::heightAt` and `panels/inspector.js::update` derive displayed values. | Simulated truth and derived values, not aircraft telemetry. |
| Radar azimuth / elevation / SNR | Source fields `az_deg`, `el_deg`, `snr_db`; azimuth clockwise from north, elevation above local horizontal. | `mirrorworld/sensors/radar.py::_plots` calculates noisy radar plots from modeled geometry, RCS, range and detection probability. | Synthetic radar capability exists in source, but this is **not in the current public `MW` bundle/UI**: `export_data.py` does not serialize radar plots into `MW.rf`. |
| Heading | Current public `MW.objects` and `MW.rf` do not carry a displayed heading. | Python truth `heading_deg` is derived from velocity in `mirrorworld/truth.py::simulate`; radar `heading_deg` is estimated by `_track`; neither is exported by `export_data.py`. Browser `game/sim.js::moveDrone` derives an internal radians heading from route motion for sprite rotation; `recordTracks` does not store it. | No current sensor-heading readout. Any game sprite heading is simulated motion, not a heading measurement. |
| Terrain / DEM | `MW.terrain.h`, metres on a 601×601 stored grid; bilinear sampling. The “DEM samples” label counts grid cells, not physical resolution. | `mirrorworld/world.py::World._fetch` downloads Copernicus DEM GLO-30 and resamples it; exporter writes `world.grid`; frontend interpolation is `dashboard/src/data.js::heightAt`. | Real elevation source used by a synthetic scenario; interpolation/grid density is not accuracy. Browser worlds instead use AWS Terrarium tiles in `dashboard/src/game/world.js::loadTerrain`, resampled onto the browser grid. |
| Terrain-shadow overlay / 40 m AGL | Red cells mark locations whose required line-of-sight height exceeds the selected slider height; 40 m is a UI threshold, not a sensed aircraft height. | Python `World.min_visible_agl` → exporter’s 121×121 `MW.shadow[*].agl` raster (about 150 m spacing); `dashboard/src/layers/shadow.js` compares it with `state.shadowHeight`. | DEM-derived visibility estimate, spatially coarser than the source DEM; not measured coverage. Browser detections use simpler range + terrain-LOS rules. |
| Sun elevation | UI `SUN …°`; geometric solar elevation in degrees, not satellite/radar elevation. | `dashboard/src/globe.js::sunElevation` computes an approximate solar position from scenario date/location (no atmospheric refraction). | Calculated value, not a sensor measurement. |
| Sensor down / health | Python `sensor.dead_t` is a modeled failure time. Browser-game HP is a game-state counter. | Exporter derives `dead_t` from configured `destroyed_by` and that object’s truth-track end; browser HP starts from `dashboard/src/game/assets.json`, then `game/sim.js::damage` changes it and `game/layer.js` renders it. | Scenario event / invented game durability, not live receiver-health telemetry. |

## Media, audit, and source gaps

- EO1 frames are rendered scenes (`mirrorworld/sensors/camera.py`), not camera recordings. IQ1 images are spectrograms from synthesized IQ (`rf_iq.py::synthesise_snapshot`), not SDR captures. The shipped archive contains the four PNG spectrograms, not raw SigMF IQ samples.
- SAT1 uses a real Sentinel-2 L2A background from another acquisition day and modeled object stamps at the scenario pass time (`mirrorworld/sensors/satellite.py::_capture`). It is not an image of the simulated flight captured at that time. The browser bundle carries a background scene ID/credit, but not the satellite sensor’s full `status.json` provenance.
- MIC1/MIC2 are declared, and `mirrorworld/sensors/microphone.py` exists, but this run explicitly skipped microphone output; there are no audio media files. The current source capability is not missing—the current run’s feed is.
- Radar, telemetry, Remote ID, human reports and C2 generators exist in source, but this exporter does not expose their observation streams as dashboard metrics. Separately, `generate_scenario.py::observations` collects `detections.csv`, `plots.csv`, `messages.csv` and `reports.csv` into its JSON summary; that summary is not the dashboard's `MW` schema. Current `MW.sensors` counts declared/configured sensors, not sensors with exported readings. Do not describe absent old-demo rows as absent source-code capability.
- `MW.provenance` currently records DEM sources, skipped sensor types, truth downsampling and shadow-grid spacing; it does not record all RF model settings, EO/IQ generation provenance, or per-SAT1 scene status. The archive’s media references are present, but those provenance details are not.
- Browser-generated `.game` data logs simplified detection intervals from `dashboard/src/game/sim.js::scan` and `trackLinks` (range + terrain LOS). It does not generate RF bearings, SNR, power, uncertainty, or position fixes. Treat missing audit output as **not audited**, not a pass; show no one-shot score unless a baseline is supplied.
