# OASIS Night Glass review

The v2 review used the frozen Ros valley demo at 1440×900 and 1920×1080. The initial v1 screenshots remain in `pass-*`; each v2 stage has paired screenshots and a console log.

| Stage       | Critique                                                                                                                                                      | Revision                                                                                                                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v2-before` | Full-height rails dominated the screen; a brown tray and dense labels competed with the data.                                                                 | Set the scene first: local Sentinel texture, labelled relief, terrain-aligned objects, semantic colours and visible attribution.                                                                           |
| `v2-scene`  | Real fields and ravines were visible, but broad bloom washed out the landscape and the old panel structure still boxed it in.                                 | Restrict bloom to bright saturated signals. Replace rails with floating cards, a compact status pill, an icon rail and six analysis tabs.                                                                  |
| `v2-layout` | Typography and spacing had a clearer hierarchy. The camera still cropped the island and motion lacked a deliberate entry.                                     | Widen the home framing; add the opening, mode transitions, count-up telemetry, Cinema and eased chapter flights.                                                                                           |
| `v2-motion` | The complete slab fit the viewport. Concentric green light pools consumed too much of the accent budget; automatic intro completion focused a toolbar button. | Replace the rings with one faint neutral radial light pool. Restore focus only after an explicit skip or when focus would otherwise remain hidden. Apply restrained exposure grading from solar elevation. |
| `v2-final`  | Fields and ravines remain readable, the slab has clear edges, and the controls leave most of the terrain open.                                                | Give PRESENT a full-width lower third and large, dataset-derived metrics. Keep missing baseline/audio explicit. Verify opening, satellite detail, Cinema and all ten chapters.                             |

Cards use 16 px padding, 24 px outer margins and semantic CSS colours. Visible quiet labels use a lighter mix of `--text-3` and `--text` for contrast over glass. Values and identifiers use Geist Mono; the wordmark and chapter/audit numerals use Unbounded. The slab's glow stays neutral so the brand accent marks controls, selection and the rim. Responsive checks also cover 1280×720 and 390×844.

The final deliverables in `../screenshots/` show DELTA at dusk, terrain dead zones, the audit, the opening title and a PRESENT chapter. The frozen dataset reports **9 PASS, 0 FAIL, 1 SKIP**, with no one-shot baseline. The illustrative comparison in the brief is intentionally not substituted for real results. EO and satellite media in this demo arrived after the original v1 captures.

The production browser checks use the nested path `/nested/console/` and verify scenario imports, mode separation, missing data, audio, all ten chapters, reduced motion and the new layout. Application exceptions and console errors fail the run. The initial intro test waits for completion before exercising the controls; a separate replay checks completion and skipping, avoiding a click racing the automatic dismissal.

Automated Chromium uses SwiftShader, including when launched without a renderer override on this host. Readback performance warnings are driver diagnostics, not evidence of device frame rate. **The 60 fps target has not been benchmarked on a physical MacBook Air.** The application uses pooled rays, bounded windows, sampled positions and Cesium request-render mode; one finite idle drift ends after eight seconds or on interaction.
